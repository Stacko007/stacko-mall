# 商城待完善事项

业务功能完善的分阶段执行计划见 [development-plan.md](development-plan.md)。本文档保留上线前生产化事项和中长期技术演进事项。

## P0 上线前必须完成

1. **数据库迁移链**：当前以 `docs/database/rebuild-stacko-mall.sql` 作为空库基线，正式上线前必须补齐 Flyway 或等价迁移链。
2. **多实例定时任务**：订单超时关闭任务当前应只开一个实例；上线前需要分布式锁、统一调度或明确单实例执行策略。
3. **端口隔离**：商城后端端口只能允许 Gateway 和受控运维网络访问，不能公网直连。
4. **生产压测**：完成下单扣库存、支付、关闭订单释放库存、售后退款等核心链路压测。
5. **支付安全**：当前支付为 Mock；接真实渠道前必须补齐回调验签、证书/密钥管理、幂等、对账和退款审计。

## P1 近期演进

1. **用户投影同步**：商城成员展示信息目前按需本地快照，账号资料或成员状态变化缺少可靠事件同步。
2. **库存并发验证**：继续完善并发扣减、释放、退款补偿和异常回滚测试。
3. **业务事件可靠性**：订单、支付、售后之间尚无 Outbox 或消息最终一致性方案。
4. **身份密钥轮换**：商城只支持单个 Gateway HMAC 密钥，缺少 `keyId` 和新旧密钥并行验证。
5. **可观测性**：补齐订单、支付、售后、库存核心指标和告警。

## P2 后续优化

1. **真实商品能力**：补齐类目、图片、上下架审核、价格策略和 SKU 维度库存。
2. **C 端体验**：补齐地址、优惠、搜索、支付结果轮询和订单售后进度。
3. **运维工具**：增加业务数据修复、幂等记录查询和异常订单处理后台。
