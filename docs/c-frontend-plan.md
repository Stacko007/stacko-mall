# C端前端开发计划（React）

> 目标：在不与服务端开发计划混淆的前提下，完成商城 C 端（用户侧）React 页面与基础交互，覆盖浏览、购买、支付、订单与个人中心等核心流程。

## 1. 范围与边界
- 范围：仅 C 端前端页面与交互（React）。
- 非范围：服务端接口开发、后台管理端页面。
- 约束：以现有接口为准，若缺少接口则记录为联调阻塞项。

## 2. 技术栈与工程约定
- React + TypeScript（推荐，若仅 React 也可在落地时确认）。
- 路由：React Router。
- 状态管理：Redux Toolkit / Zustand（二选一，落地时确认）。
- 请求库：Axios。
- 样式：CSS Modules / Tailwind / Styled Components（三选一，落地时确认）。
- 构建：Vite。

## 3. 目录与模块拆分建议
- pages：页面级组件。
- components：通用组件。
- services：API 请求封装。
- store：状态管理。
- hooks：业务 Hook。
- assets：静态资源。
- utils：工具函数。

## 4. 页面规划（按业务流）
1. 首页：Banner、分类入口、推荐商品、搜索入口。
2. 分类页：分类列表、商品筛选/排序。
3. 搜索页：关键词搜索、历史记录、热词。
4. 商品列表页：列表/瀑布流、筛选/排序、分页/无限滚动。
5. 商品详情页：图文、规格、库存、评价、加入购物车/立即购买。
6. 购物车页：商品勾选、数量调整、价格汇总、去结算。
7. 确认订单页：地址选择、优惠券、运费、提交订单。
8. 支付页：支付方式、支付状态提示、结果页。
9. 订单列表页：全部/待付款/待发货/待收货/已完成。
10. 订单详情页：订单信息、物流信息、售后入口。
11. 个人中心页：用户信息、地址管理、优惠券、我的评价。
12. 登录/注册/找回：账号体系入口。

## 5. 细节清单（更细）
1. 工程与基础设施
- Vite 初始化、环境区分、打包配置。
- 路由结构与布局骨架（头部/底部/浮动购物车等）。
- API 层封装（拦截器、错误码处理、重试/降级策略）。
- 全局状态管理（用户、购物车、订单临时状态）。
- 统一样式与主题变量、响应式断点。
- 通用组件库：按钮、输入框、弹窗、列表、卡片、空状态、加载态。

2. 登录与用户体系
- 登录/注册/找回密码页面。
- 账号与 Token 存储、登出流程。
- 登录态路由守卫与页面重定向。

3. 浏览与搜索
- 首页模块化组件（Banner、分类、推荐）。
- 分类页与商品列表页筛选/排序。
- 搜索联想、历史记录、热词展示。
- 商品详情（规格、库存、评价、图文）。

4. 购物车与下单
- 购物车勾选、数量、价格汇总、失效商品处理。
- 收货地址选择/管理入口。
- 优惠券选择与金额展示。
- 订单提交与防重复提交。

5. 支付与结果
- 支付方式选择与支付跳转/唤起。
- 支付结果页与订单状态刷新。

6. 订单与个人中心
- 订单列表多状态筛选与分页。
- 订单详情、物流信息展示。
- 个人信息、地址管理、优惠券、评价入口。

7. 体验与质量
- 骨架屏、加载态、空态覆盖率。
- 移动端适配与主流机型测试。
- 性能优化（图片懒加载、列表虚拟化可选）。
- 异常捕获与日志上报（可选）。

## 6. 里程碑与排期建议
1. M1（基础框架）
- 初始化前端工程、路由与布局。
- 全局样式、主题与基础组件（按钮、弹窗、列表、分页）。

2. M2（浏览与搜索）
- 首页、分类、搜索、商品列表、商品详情页面完成。
- 与商品相关接口完成联调。

3. M3（下单与支付）
- 购物车、确认订单、支付页面完成。
- 订单创建/支付状态接口联调。

4. M4（订单与个人中心）
- 订单列表/详情、个人中心、地址管理、优惠券页面完成。
- 用户信息与订单接口联调。

5. M5（体验与验收）
- 埋点/异常捕获（可选）。
- 性能优化、兼容性与回归测试。
- UI/交互细节打磨。

## 8. 联调清单（示例）
- 商品：列表、详情、库存、评价。
- 购物车：增删改查、选中状态。
- 订单：创建、支付、取消、详情、列表。

## 9. 风险与依赖
- 接口缺失或变更导致联调阻塞。
- UI 设计稿延迟或变更频繁。
- 移动端适配与多端兼容需求不明确。
